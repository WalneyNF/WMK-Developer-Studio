Estado real da base

Legenda: “Existe no código” indica arquivos e configurações encontrados no repositório, não validação de funcionamento. “Planejado” indica desenvolvimento futuro. Os itens assinaláveis abaixo são pessoais e ficam salvos apenas neste navegador.

EXISTE NO CÓDIGO

Editor e linguagens

CodeMirror, detecção de linguagens, realce de sintaxe, integrações LSP e DAP. Existem definições para C#, C++, GDScript, HTML, CSS, JS, TS, Python, PHP, Rust e mais.

EXISTE NO CÓDIGO

Ferramentas de programação

Git, terminal, busca, execução e depuração, cliente HTTP, banco de dados, testes e ferramentas de análise. Necessitam ensaios na versão WMK.

EXISTE NO CÓDIGO

Agentes ACP e servidor MCP

Agentes externos por Agent Client Protocol; interface de servidores MCP externos; servidor MCP local da IDE. ACP, MCP e APIs LLM são interfaces distintas.

EXISTE NO CÓDIGO

Plugins WebAssembly

Instalação, permissões, novos comandos, temas, linguagens, painéis e editores; API ainda em preview. Plugin oficial AI Completion declara Ollama e OpenAI.

Fases do desenvolvimento

Fase 0 — Build de referência e identidade WMK

Objetivo: baixar e abrir um aplicativo Windows, detectar falhas reais e só depois ampliar funcionalidades.

Fase 1 — Tradução e ergonomia

Objetivo: interface pt-BR, layout flexível, menus entendíveis, documentação e configurações persistentes.

Fase 2 — Ferramentas GameDev + IA

Objetivo: plugins por engine, assistência de código e conectores de IA com controle de permissões.

Fase 3 — Criação assistida e distribuição

Objetivo: templates, designer visual, testes automáticos, releases e extensões independentes.

IMPLEMENTADO NO CÓDIGO • PENDENTE DE TESTE

WMK AI Code Actions — primeira entrega

Quatro comandos no editor e na lista de ações: Explicar código, Revisar código, Propor correção e Gerar testes. Usam a infraestrutura ACP existente, anexam referência ao arquivo e abrem um rascunho; não enviam automaticamente a tarefa nem alteram arquivos antes do início pelo usuário.

P0 • SEGURANÇA

WMK Safe Changes

Revisão de diferenças por arquivo e trecho, checkpoints Git, opções de aceitar/rejeitar e reversão segura. Aproveitar worktrees e diffs já presentes, sem destruir alterações existentes. Exigir permissões específicas para execuções sensíveis.

P1 • EXPERIÊNCIA DE IA

WMK AI Control Center

Painel de agentes e provedores: Codex, OpenCode, Gemini CLI, Groq via agente compatível, Ollama e OpenAI. Exibir instalações, conexão, modelos disponíveis, latência, limites, erros, autenticação e consumo quando fornecido pela API.

P1 • QUALIDADE

WMK AI Reviewer e Smart Debugger

Revisar mudanças Git com evidências, gravidade, arquivo e linha; reunir erros de compilação, testes e depurador e gerar solicitações contextualizadas para o agente. Separar resultados realmente executados de sugestões não verificadas.

P2 • INTELIGÊNCIA DO PROJETO

WMK Project Intelligence

Índice local do projeto: módulos, símbolos, dependências, APIs e referências; busca contextual relevante para agentes, com limites de tamanho e exclusão de segredos e arquivos privados.

P2 • CRIAÇÃO

WMK Project Creator

Assistente de contratos de projeto, templates web/PHP/Python/Godot, planejamento por etapas, geração e testes de aceite. Entregas incrementais; não prometer geração perfeita de jogos completos sem validação.

P3 • AUTOMAÇÃO

WMK Multi-Agent Studio

Orquestração de arquitetor, programador, testador e revisor com isolamento por tarefa, registro de prompts, diffs, comandos, custos e decisões. Evitar loops sem limites, instalar dependências ou publicar código sem aprovação.

P2 • EDUCAÇÃO

WMK AI Professor

Explicações passo a passo, exercícios, perguntas e revisão comentada de código com níveis iniciante, intermediário e avançado. Preferir explicações baseadas nos arquivos e testes reais.

IA • PRIORIDADE ALTA

Agentes ACP e provedores LLM

Testar Claude Code/Codex/Gemini CLI via ACP. Aproveitar plugin Ollama/OpenAI para completions e criar integração Groq (quando aplicável); guardar chaves no cofre do sistema, controlar tokens/latência.

MCP • SEGURANÇA

WMK MCP Tools

Auditar servidor local, ferramentas expostas, permissões, consentimento, logs, segredos e limite de execução. Criar exemplos Git, banco, editor e diagnósticos.

Estratégia WMK de compilação e distribuição

Workflows implementados no GitHub, mas executáveis ainda dependem de uma compilação concluída e de testes no Windows.

IMPLEMENTADO • CI

WMK Quick Check

Compila frontend TypeScript/Vite em pushes relevantes, sem gerar instalador. Evita usar o empacotamento Tauri para alterações menores. O CI original continua separado.

IMPLEMENTADO • TESTES WINDOWS

WMK Windows Test (EXE)

Compilação Windows x64 com --debug --no-bundle para pular NSIS, gerando ZIP com EXE de testes e hashes. Execução manual para não disparar uma compilação pesada a cada commit.

Ver workflow
IMPLEMENTADO • RELEASE

WMK Windows Release

Build otimizada e NSIS mantidos, agora acionados manualmente. Relatório de artefatos e hashes; evita compilação release automática em cada alteração de código.

Ver workflow
A MEDIR • PERFORMANCE

Otimizar cache e observar duração

Cache Rust separado para debug e release. Medir hits, tempo de compilação, tamanho dos artefatos e custo de recursos antes de decidir por sccache ou runners diferentes. Perfil Cargo wmk-test existe, porém não está ativado no Tauri.
